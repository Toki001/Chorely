## Implemented

Accepted one-off/recurrence/completion changes atomically enqueue durable private
source revisions. A bounded worker reconciles current state/authorized recipients,
uses a lease and retry isolation, and publishes one private inbox message per
stable event. Five failed source attempts need operator attention. Preference and
membership/device changes enqueue generation-checked, 25-occurrence refresh pages.
Re-enabling policy includes chores created while opted out and preserves reads.
No task state, template or progress figure is mutated by notifications.

Current member/account/profile authorization gates adult-private preferences,
guardian-managed child preferences, child-own inbox, plan signals and server opens.
All client writes remain denied. Existing M05 adult profiles without a status
field remain valid; child profiles require explicit active status. Save commands
use payload-bound UUID receipts, CAS, expected timezone, quota and minimal audit.
Read acknowledgements use a fixed message ID/first server timestamp and quota;
plan generation is separately bounded/rate-limited. Own-part completion suppresses
nags; review goes only to a separate eligible guardian. Fixed lock-screen copy
excludes names, task titles and notes.

IANA quiet-hour intervals handle spring gaps and full repeated hours (earlier
start/later end), including half-hour transitions and missing days. Assignment
identity changes for actual ownership/schedule revisions rather than help edits
or preference versions. Expired/cancelled/terminal plans are invalidated.

Flutter provides a real private Updates screen, recent actual unread counts,
authorized detail navigation and preferences. Child policy is read-only; guardians
can select active child profiles, never another adult's private policy. Uncertain
saves retain the same frozen payload/UUID; conflicts require reload. Cold links
wait for authentication restoration, reject the wrong profile and invalidate
late responses/routes on account changes. Missing/deleted/reassigned targets have
a safe fallback. A local alert preceding worker publication may open only through
an unexpired owned private job with matching current versions.

Native local reminder adapter initializes without prompting. Explicit device
opt-in requests/checks OS permission; server policy separately allows local
reminders. At most 60 reminders/24 hours reserve four iOS slots; Android uses
inexact alarms with no exact-alarm permission. Private signals/preferences,
foreground minute/resume/manual refresh rebuild plans. One active home/profile owns
this installation; leaving that home cancels its reminders, as explained in preferences. SQLite persists opaque
scopes/opt-in, stable monotonic integer OS IDs and attempt times, with FULL
synchronous transactions. Immediate attempts persist before OS calls to avoid
replay after an ambiguous crash; this may lose an alert. Future reschedules
replace the same ID; initial sync suppresses old alerts. Identity/access changes,
policy disablement and obsolete plans cancel alarms. No local record is called
OS delivery. Offline/terminated devices can still show an unseen stale generic
alert; a tap always reauthorizes.

Pinned dependencies: firebase_messaging 17.0.1, flutter_local_notifications 22.3.3,
timezone 0.11.2 and sqflite 2.4.5. Actual installed APIs/README and firebase-admin
14.5 types were read. Current FCM uses installation-ID registration; deprecated
token-only samples were not copied. Demo auto-init/registration are disabled.
Android permission/receivers/desugaring/original monochrome home-check icon and
iOS notification-center/UIScene integration are authored. No APNs entitlement,
account connection, service registration, signing change or provider send occurred.

## Failures corrected

A strict status check originally rejected M05 adult profiles; optional adult status
is now supported while child status stays explicit. Sparse recurrence cancellation
patches initially appeared to remove owners; a tested helper preserves absent
assignment fields. Adding the reminder-channel dropdown required the guardian
widget test to identify its target dropdown explicitly. Native async route
transitions briefly expose two Back buttons; the test now waits for exactly one.
A native ledger assertion initially failed because Flutter's integration runner
uninstalls the application by default, clearing SQLite (iOS Auth Keychain survives).
The installed SDK's `commands/test.dart` and `integration_test_device.dart` confirmed
this behavior. The runner now uses `--no-uninstall` for actual process restart
persistence rather than comparing across application removal.
A queued-jobs-only preference sweep could not restore disabled notifications;
it now pages real occurrences, including rows that never had jobs.

## Remaining gates and continuation

M11 is not fully accepted for release. FCM/APNs live project authorization and
credentials, modern installation-ID registration/rotation/revocation and provider
adapter/current-state dispatch integration must be implemented/tested together in
an authorized staging environment. Provider attempted/accepted/uncertain and OS
read/delivery observations must stay distinct. Current schema reserves `push`,
but UI offers in-app/local and no remote dispatch is enabled. No fake registration
or delivery evidence is substituted.

Physical iOS/Android permission allow/deny/revoke, background/terminated/reboot,
battery restrictions, remote cold delivery, hardware and signing remain unverified.
Production indexes, scheduler/IAM, queue retention/attention tooling and cost/load
limits need authorized rollout and M16–M18 hardening. Existing global account/profile
revocation/cache concerns from M09 remain M16 gates; this is not a full privacy
or security audit. No actual minors' data was used.

Continue independent M12 durable offline command/reconciliation work after the
verified local M11 commit. This dependency adjustment leaves M11 provider gates
open and does not claim multi-device/offline reliability prematurely. See
`ADR/ADR-008-notification-delivery.md` and LOCAL_DEVELOPMENT for concrete setup.
