## Delivered independent slice

`functions/src/postpone.ts` adds current-guardian authorization, eligible-assignee
and review validation, occurrence CAS, payload-bound UID/UUID receipt and a daily
quota. It changes one uncompleted occurrence to a later server-validated deadline
within thirty household civil days, preserving ID/slot/template/rule/assignment/
completion. Untimed chores move to a later day. Shared IANA gap/overlap handling
applies. Current partial work, terminal/review-waiting states and stale/removed
access are rejected. Actual activity records previous/new schedule and versions.

Explicit overrides survive automatic recurrence refresh and future rule pauses.
Notification outbox writes commit with the occurrence. Reconciliation cancels old
timing jobs and creates current ones. Assignment IDs use owner generation/set,
preventing a second assignment alert when only the deadline changes. No provider
send or live data migration/deployment occurred.

The guardian form uses a separate scheduling repository boundary. Uncertain retry
freezes ID/base/date/time; conflict/permanent rejection stops replay and requires
successful current-state reload. Callable acknowledgement plus a fresh read
precedes success. Detail/cache show the actual deadline and postponed state.
Children/ordinary adults and partially completed tasks do not expose the action.
The form explicitly explains that selecting a deadline replaces a time window.
This online authoring flow is outside M12's durable completion journal. ADR 010
records policies and limitations.
