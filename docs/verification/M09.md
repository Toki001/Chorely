Implemented trusted occurrence complete, own undo, help, separate-guardian
approve/redo and manager help acknowledgement. Current server membership/profile
resolves the actor; supervised devices share a stable profile contribution. Body
role/UID/clock fields have no authority. Each action persists state, receipt, rate
and accepted activity atomically. Any-one/all-member completion uses real stored
contributions. Optional review enters pending state and cannot be self-approved.

Undo is bounded by five server minutes and dependent completion revision. Redo
requires feedback and preserves previous review audit. Help never completes a
chore; private notes are available to their actor and current chore managers.
Denied self-review is logged privately, outside accepted-only activity. Partial
work fences edits, automatic reconciliation and duplicate one-off conversion.
Definition edits audit prior/new assignees. See ADR-006 for policies and limits.

App controls reflect current stored contributions/status and current role. Unknown
requests freeze their ID/base/note for retry, while known conflicts require reload.
No optimistic remote success or fabricated progress. Child mode never queries
other actors' notes or privileged activity. Guardian history is ordered by version,
so equal server timestamps retain causal order. Completed chores can still start a
future repeat configuration without rewriting the completed occurrence.
